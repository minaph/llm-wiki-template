# Run Note — RUN-YYYYMMDD-NNN

`task` はカンマ区切りで、このRunで実行したTaskを列挙する。標準2Slot+EではWork 1、Work 2、Slot Eの順に記す。Work 1がTaskに基づかない直接依頼なら最初の値を `direct-request` とする。同じTaskをWork 1 / Work 2で独立した作業として選んだ場合は同じIDを二回書いてよい。

## 作業前の確認 — TODOと2Slot選択

作業開始時に [TODO](../TODO.md) をその都度読み直し、新しい要望、優先度変更、完了済みなのに未更新の項目を確認した結果を書く。

- **Work 1:** Task IDまたは `direct-request`。選択理由と今回の判別可能な問い。
- **Work 2:** Task ID。Work 1とは別の問い・主な根拠面・判断差を持つ理由。
- **Slot E:** `WIKI-EDITORIAL-QUALITY`。Work 1 / Work 2の成果物や中心主題を避けて選んだ既存Wiki Entry。

同じTaskを二枠に選んだ場合は、`問い / 主な根拠面 / 判断差 / 停止条件` がどのように分離しているかを書く。

## Work 1

### 今回の範囲と一次資料

今回調べた範囲、コード、要求、Wiki、外部資料等への参照を書く。

### 観察・実行・判断

直接確認したこと、推論、実行した検証、クライアント確認を必要に応じて区別する。実行した場合はコマンド、環境、対象コミットや版、未コミット変更、ログ、終了コード、生成物への参照を残す。

### Wikiへの反映

結果・適用条件・設計判断・再利用可能な知識を書いたWiki文書へリンクする。Wikiを変更する必要がなかった場合は、確認した文書と変更不要と判断した理由を書く。

### Run-level contribution claim — Work 1

「何をしたか」ではなく、**今回のWorkが既存理解へ何を加え、変え、限定し、反証し、または実行確認したか**を一つ以上の判別可能な文で書く。可能なら対象のWiki Entry-level claimへリンクする。

既存Wikiの特定claimを実質的に利用・変更した場合は、必要に応じて対象命題を特定して記す。

- **SUPPORT:** 支持する命題の短い引用、見出しまたはClaim番号、参照時のコミットSHAと文書への参照、今回追加した根拠。
- **CHALLENGE:** 懐疑・限定する命題の短い引用、見出しまたはClaim番号、参照時のコミットSHAと文書への参照、今回の反証・境界。

未コミットの文書やGit管理外の資料の参照方法は、[既存claimへの反応](../TASK_SYSTEM.md#既存claimへの反応)に従う。Work 2とSlot Eでも同じ項目を記録する。

ファイルを参照しただけでSUPPORTとしない。同じRun内の自己支持を後続評判の証拠として数えない。

## Work 2

### Taskと独立性

Task ID、今回の問い、Work 1とは異なる主な根拠面と判断対象を書く。Work 1の成果がWork 2の対象を直接生成した場合は、独立Workではなく直列工程だった可能性を記録する。

### 観察・実行・判断

Work 1と同様に、直接確認、推論、実行証拠、外部確認を区別する。

### Wikiへの反映

今回の成果を反映したWiki、または変更不要と判断した根拠を書く。

### Run-level contribution claim — Work 2

Work 2が既存理解へ与えた知的差分を記す。Work 1と無理に一つの物語へ統合しない。

既存claimへの反応がある場合は、Work 1と同様に対象命題を特定してSUPPORT / CHALLENGEを記す。

## Slot E — Wiki内部品質の独立点検

### 対象選択

[Wiki内部品質の独立点検](../tasks/wiki-editorial-quality.md) に従い、Work 1 / Work 2で新設・実質改稿・中心参照した文書や同じ判断系列を避けて選んだWiki Entryを書く。完全に無関係な文書を選べなかった場合は、その制約も書く。

### 診断・改稿・読み直し

中心claim、根拠、適用範囲、反例、用語、文章構造、リンク、正本境界を通読して確認した結果を書く。改稿した場合は何を変えたか、変更不要ならなぜ十分だったかを書く。

大規模な設計再判断、追加調査、実行検証が必要な問題を見つけた場合は、Eの中で憶測して埋めず、後続Taskまたは作業候補へ形成する。

### Run-level contribution claim — Slot E

EがWiki内部品質へ与えた知的差分を記す。単なる「校正した」ではなく、どのclaim範囲、根拠接続、用語、構造、正本境界を明確化・限定・修復したかを書く。変更不要だった場合は、どの品質条件を確認し、なぜ現状維持を選んだかを書く。

既存claimを実質的に支持・懐疑した場合は、対象命題を特定してSUPPORT / CHALLENGEを記す。

## 横断的な貢献主張 — 任意

Work 1とWork 2が、独立に進めた結果として同じ上位原理へ実質的に収束した場合だけ書く。二つのWorkを一つの物語へまとめることを完了条件にしない。

横断主張が非常に自然に成立する場合は、Work 1がWork 2の対象・問いを生成して直列化していなかったかも確認する。Slot Eは独立した品質管理の枠なので、Workとの横断物語へ無理に統合しない。
