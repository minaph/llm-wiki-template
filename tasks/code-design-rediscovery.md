# コードと履歴からの設計調査

## 目的

現行コードとGit履歴を調べ、文書化されていない動作上の約束、責任分担、互換性の条件、過去の判断理由をWikiにまとめる。

## 判断対象

一つのモジュール、外部との入出力、データ経路、期間を絞った変更履歴、または設計の転換点について、現在維持すべき動作・互換性の条件は何か。

## 一次資料・証拠

現行コード、代表的なコミットと差分、READMEや既存文書、テスト、Issue・PR。Wikiの説明だけで過去の実装や変更理由を確定しない。

## 必要な行為

現在の構造と、主要な責任分担や入出力の仕様が導入・変更されたコミットを確認する。観察と解釈を分け、維持すべき条件、意図的に変更できる部分、未検証の前提を整理する。

## 一回の作業の完了条件

一次資料を確認し、構造と変更履歴から分かった設計・判断理由・未確定事項をWikiへまとめる。必要な検証Taskを作成し、調査範囲と作業経緯をRun Noteに残す。既存説明で十分なら、変更不要と判断した根拠を記録する。

## 品質基準

出典をたどれること。過去の判断を当時の要求・制約に照らして説明し、現在の判断と区別する。ファイル構造だけでなく維持すべき動作を説明する。変更した文章を読み直す。

## 存続形態・終了条件

常設。未点検領域や重要な設計変更が生じたときに実施する。調査対象がなくなった場合は休止し、新しい対象が生じたら再開する。システムの保守終了または責任の移管時に終了する。

## 停止・引継ぎ

履歴や原資料にアクセスできない場合は、不明な設計理由を断定せず、不足資料を記録して保留する。資料が得られたら再開する。実行確認が必要な事項は検証Taskへ引き継ぐ。
